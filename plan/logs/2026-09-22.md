## Sidebar motion

Used the improve-animations skill for a focused review of the requested sidebar.
The user's implementation request took precedence over its planning-only posture.

| Before | After | Why |
| --- | --- | --- |
| Sidebar removed immediately | Existing 200 ms quintic ease-out, sliding fixed-width contents through a clipped viewport | Preserve spatial context |
| Repeated toggles snap | Retarget from current progress | Keep reversal continuous |
| Reduced motion still scheduled timers | Immediate change without timer work | Respect the preference |
| Frosted target would resize each frame | Disable optional viewport capture during the transition | Avoid texture allocation churn |

The native virtualized library reflows while its available width changes. This is
an explicit GPUI compromise; no browser transform/performance claims apply.
