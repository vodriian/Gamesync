### Design review

| Before | After | Why |
| --- | --- | --- |
| Eagle's square asset tiles and file metadata | Portrait covers, game captions, and game details | Fit the library task while retaining the proven layout |

| Arrow selection recenters visible rows | Reveal only rows outside the viewport | Keep navigation steady |

## Commit and storage file layer

### Changes

- Committed the documented native demo as `71fcea7` (`feat: add native game library demo`).
- Started platform-independent storage work while Linux UI checks remain pending. Added no screens.
- Added a small Rust library module for JSON publication. It retains an immutable revision before replacing a current record.
- Stage files beside their destination, flush their contents, and sync directory entries after publication. Temporary files have a `.tmp` suffix.
- Reject revision-path reuse with different content. Permit an exact retry after a failed current-file save.
- Use the already locked `tempfile` package. Eagle has no matching revision writer to reuse.
- Keep the file layer separate from the demo. Schema validation, safe path selection, revision parents, and conflict checks are caller requirements.

### Validation

- macOS arm64: all 20 tests passed, including eight new storage tests.
- Formatting and Clippy with warnings denied passed. The dependency lock adds no new package.
- Tested retained revisions, exact retry after current-file failure, missing history, serialization failure, incomplete temporary files, concurrent revision publication, and reads during replacement.
- Failure cases use controlled filesystem conditions. They do not simulate physical power loss, Dropbox synchronization, or disk removal.
- Linux checks remain pending. Windows writes return an unsupported-platform error.
