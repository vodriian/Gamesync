## Data sync step 3: local connection

- Added `project.rs` (local library and shared settings as sync fields),
  `apply.rs` (received values through the guarded library writes and settings),
  and `engine.rs` (rounds, device state file, outbox, resolution, and a new
  device ID after a duplicate).
- Design change, recorded in [Data sync](../data-sync.md): a three-way
  comparison of local, known, and folder values replaces hooks in each save
  path. Joining is the first round with nothing known.
- Found and fixed while testing:
  - An absent game (archived or unreadable) looked like cleared values and
    would have cleared them on other devices. The projection now lists
    present targets, and absent targets are never read as edits.
  - New-library definitions (built-in statuses, order, labels) conflicted at
    join. They now count as unset.
  - A missing sync folder was created again on the local disk by the writer.
    Scans and writes now fail when the folder is not available.
  - Conflicts made at join now show in the same round.
- Deferred: override cover media, manual games, and the archive state; no
  current feature needs them. The bound Steam account does not sync.
- Tests: 7 in `tests/sync_engine.rs` with two real libraries (settings,
  statuses, collections, and personal data reach the other device; sequential
  and concurrent edits with resolution; join; a missing game; restart; offline
  folder; copied app data), plus 2 unit tests.
- Checks on Linux: `cargo fmt --check` passed; full suite 150 passed, 7

## Data sync step 5: encrypted keys

- Added `desktop/src/sync/secrets.rs`: a random age X25519 sync key protected
  by the passphrase (age scrypt), sealed API keys with keyed SHA-256
  fingerprints, and fingerprint comparison in the engine. Design change from
  the plan: the passphrase protects only the sync key, because scrypt is too
  slow for each round. See [Data sync](../data-sync.md).
- `OsCredential` replaces `SteamCredential` and adds the sync key entry.
- Runtime: key state, sealed Steam key in each unlocked round, received keys
  saved to the credential store, and turn on, unlock, and change passphrase.
  Settings: an **API keys** group in Sync; the Steam connection reloads when a
  key arrives.
- Dependencies: `age` 0.12.1 (`armor`) and `sha2` 0.10.
- Tests: 2 unit tests (right and wrong passphrase, recipient match, sealing,
  fingerprints) and 1 engine test (a key re-encrypted each round writes
  nothing; a new key reaches the other device).
- Checks on Linux: `cargo fmt --check` passed; full suite 155 passed, 7
  optional tests ignored; Clippy with `-D warnings` passed for GameSync.
- Native check on Omarchy with the two disposable profiles and the live Secret
  Service, with a fake Steam key for profile A:
  - A turned on key sync. The folder had only `secret:sync_key` (age text and
    recipient) and the sealed `secret:steam_api_key` (age text and
    fingerprint). The fake key text was in no folder or profile file.
  - B showed the locked state. A wrong passphrase showed "The passphrase is
    wrong" and changed nothing. The right one unlocked B. B's credential store
    then held A's key, and General showed "Steam API key saved".
  - Test credential entries were removed afterwards.
  - The app needs `DBUS_SESSION_BUS_ADDRESS` for the credential store; the
    desktop launcher has it, an agent shell does not.
- Not verified: macOS Keychain, change passphrase in the running app, and the
  conflict of two devices turning on key sync together.
