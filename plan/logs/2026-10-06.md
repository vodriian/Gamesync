## ProtonDB research

- The summary endpoint (`/api/v1/reports/summaries/<id>.json`) works but is
  undocumented. It returns a tier, score, and report count for all Linux
  reports, not only Steam Deck reports. The site's `robots.txt` blocks AI
  agents by name, so agent research stopped after five test calls.
- The monthly ODbL export (`bdefore/protondb-data`, October 2026 file:
  72 MB compressed, 395,467 reports) names the device. 54,896 reports are
  from a Steam Deck (CPU "AMD Custom APU" or SteamOS), covering 16,387 apps;
  2,602 apps have five or more.
- Deck reports for Cyberpunk 2077 (108): 28% performance faults, 33% battery
  problems, 39% readability problems. Balatro (99): 1%, 17%, 7%. Destiny 2
  (12): 1 of 12 runs. This separates heavy games from light ones where the
  Valve rating does not.
- SteamDB has no API and does not allow scraping; its Deck data comes from
  Steam, which the app already reads. Not used.
- Decision: ProtonDB becomes an opt-in Enrichment source in Settings → Best
  on, using the monthly export. See [Best on](../best-on.md#planned-rules-and-enrichment).

- Windows cannot be cross-compiled from macOS: GPUI compiles DirectX shaders
  with `fxc.exe` in its build script. Added a manual and on-push workflow
  (`.github/workflows/windows-build.yml`) on branch `windows-test-build`; it
  builds a release `GameSync.exe`, runs tests without blocking, and uploads a
  zip for 14 days. `keyring` gains `windows-native`, so keys use Windows
  Credential Manager instead of memory.
- Run 37481930480 on `windows-latest`: build passed (13 MB artifact). Library
  tests: 62 passed, 10 failed; the other test binaries did not run. All
  failures are the intended guard "Library storage is not implemented for

  durable writes are data sync step 7 and not built. The Windows app cannot
